# COP 4020 Project 1 — Banking Application (Part 1 & Part 2)

## 1. Project Overview & Architecture
This project implements a full-stack desktop banking application split across two distinct architectural layers:
* **Part 1 (C++ Backend):** Implements object-oriented data modeling (`struct Client` and `class Bank`), manual dynamic array memory management with the **Rule of Three** (destructor, copy constructor, copy-assignment operator), defensive CSV file I/O, and all business/validation rules.
* **Part 2 (C++ Wrapper & Python/Tkinter Frontend):** Exposes the C++ `Bank` backend safely to Python via an `extern "C"` wrapper layer (`bank_wrapper.cpp`) that catches all C++ exceptions at the ABI boundary and converts them into integer status codes and error buffers. The Python GUI (`bank_app.py`) uses `ctypes` and `tkinter` to provide an interactive interface without duplicating business logic in Python.

---

## 2. Repository File Structure
| File | Description |
| :--- | :--- |
| `bank.h` | Header file defining `struct Client`, `class Bank`, private dynamic array members, and public method prototypes. |
| `bank.cpp` | Implementation of all `Bank` member functions, including deep-copy memory management, CSV parsing/saving, and transaction validation. |
| `main.cpp` | Standalone C++ console test driver exercising all Part 1 backend requirements and edge cases. |
| `bank_wrapper.cpp` | C-compatible (`extern "C"`) wrapper layer managing opaque `Bank*` pointers and catching C++ exceptions for `ctypes`. |
| `bank_app.py` | Python/Tkinter graphical user interface (`BankApp` class) and `ctypes` shared-library bindings. |
| `README.md` | Build, compilation, and testing documentation. |

*(Note: Per repository guidelines, compiled binaries such as `.dll`, `.so`, `.dylib`, `.exe`, and `__pycache__` folders are excluded from version control).*

## 3. Tested Platform & Prerequisites
* **Primary Tested Platform:** Windows 11 (64-bit)
* **C++ Compiler:** MinGW-w64 / MSYS2 UCRT64 `g++` supporting C++17 (or C++23)
* **Python Environment:** Python 3.x (64-bit, matching the 64-bit `g++` compiler architecture) with standard `tkinter` and `ctypes` modules.
* *(Build commands for Linux and macOS are also included below).*

## 4. Build & Run Instructions

### Part 1: Compiling and Running the C++ Console Test Driver
Open a terminal in the project root directory and run:

#### Windows (MinGW / MSYS2 PowerShell or Bash)
```bash
g++ -std=c++17 bank.cpp main.cpp -o bank_test.exe
./bank_test.exe
```

#### Linux / macOS
```bash
g++ -std=c++17 bank.cpp main.cpp -o bank_test
./bank_test
```

---

### Part 2: Compiling the C++ Shared Library for Python (`ctypes`)
Before launching the Tkinter GUI, compile `bank.cpp` and `bank_wrapper.cpp` into a shared library in the same directory as `bank_app.py`.

#### Windows (MinGW-w64 / MSYS2 UCRT64)
We include `-static-libgcc -static-libstdc++` so the resulting `bank.dll` bundles the C++ standard library runtime directly and can be loaded by Python without requiring external MinGW DLL paths:
```bash
g++ -std=c++17 -shared bank.cpp bank_wrapper.cpp -o bank.dll -static-libgcc -static-libstdc++
```

#### Linux
```bash
g++ -std=c++17 -shared -fPIC bank.cpp bank_wrapper.cpp -o libbank.so
```

#### macOS
```bash
g++ -std=c++17 -dynamiclib bank.cpp bank_wrapper.cpp -o libbank.dylib
```

---

### Part 2: Running the Python/Tkinter GUI
Once the shared library (`bank.dll`, `libbank.so`, or `libbank.dylib`) is compiled in the project folder, launch the GUI:

```bash
python bank_app.py
```
*(On macOS/Linux, use `python3 bank_app.py` if `python` points to an older version).*

## 5. Input CSV File Format
The application reads and writes plain-text CSV files where each row represents one client record in the following order:
```text
client_name, ssn, bank_account_number, balance
```
**Example (`clients.csv`):**
```csv
Jordan Lee, 123-45-6789, 0001234567, 1250.75
Taylor Morgan, 987-65-4321, 0009876543, 500.00
```

## 6. Functional Verification Checklist
1. **Launch without initial file:** Run `python bank_app.py` and verify the GUI opens cleanly with 0 clients loaded.
2. **Load client file:** Click **Load Client File...** and select a valid `.csv` file (such as `test_clients.csv` generated by `bank_test`).
3. **Find client:** Search for `0001234567` to view the client's name, masked SSN (`***-**-6789`), account number, and formatted balance. Search for `9999999999` to verify the missing-account error dialog and status message.
4. **Deposit funds:** Enter account `0001234567` and deposit `250.25` to verify the balance updates to `$1,501.00`. Attempt a deposit of `-50` or `abc` to verify validation feedback.
5. **Withdraw funds:** Withdraw `501.00` from `0001234567` to verify the balance updates to `$1,000.00`. Attempt to withdraw `50000.00` to verify the insufficient-funds error message.
6. **Add new client & duplicate prevention:** Fill out the **Add New Client** form with a unique account number and click **Create Client Account**. Attempt to add another client with the same account number to verify duplicate rejection.
7. **Save and reload persistence:** Click **Save Data As...**, save to a new CSV file, close the GUI, reopen `python bank_app.py`, and load the newly saved file to confirm all changes persisted.
8. **Clean shutdown:** Close the window normally (`WM_DELETE_WINDOW` triggers `bank_destroy` once to free heap memory cleanly).
